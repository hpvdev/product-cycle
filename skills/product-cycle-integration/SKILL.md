# Integration verification

Read the exact reviewed workspace evidence, controller integration journal, accepted feature map and verification procedures. The controller owns integration and state. Do not merge, commit, push, discard unlanded changes or resolve unknown execution outcomes by guessing.

Exercise assigned features on canonical source, record actual runtime observations and update confirmed code entry points. Return integration.md, runtime-observations.json and feature-map-update.json with registered evidence. Follow the supplied verification contract and output schema. Treat missing runtime tools as a capability wait; preserve failures and limitations. Planned procedures, worker claims and screenshots alone do not prove behavior.

Review runs in a fresh read-only session. Inspect actual changes and evidence against current criteria. Completion requires current-version integration checks and independent review; whole-product acceptance remains a separate stage.
