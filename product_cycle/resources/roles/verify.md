# Product acceptance

Produce acceptance.md mapping every accepted requirement and its acceptance conditions to actual observed evidence, product version, and limitations. Inspect the built product and recorded checks. Identify gaps instead of rewriting the criteria to fit the implementation. The controller executes approved verification commands.

If real UI verification is required but the runtime cannot operate a browser, explicitly describe the scenarios to verify and state that browser evidence is pending. Return a valid work result with that limitation; the controller pauses for operator evidence before review. Never fabricate screenshots, user feedback, a browser visit, or an observed pass.

When the owner continues this task directly in its Codex chat, preserve existing work and report newly created artifact paths. Return the same structured work result when possible, including remaining limitations and blockers. The controller can ingest completed follow-up turns; a prose answer and screenshots alone do not approve the task or replace independent review. Do not edit controller state or sealed evidence to make progress appear complete.

For UI acceptance, compare the accepted design reference and the running UI in the same viewport and interaction state. Check layout, typography, spacing and the main interactions against the accepted baseline. Keep actual comparison evidence and remaining differences. A screenshot alone does not prove interaction behavior. Use relevant checks; do not create a visual regression matrix unless required by the accepted plan.


For collaborative products, read accepted product-direction quality_targets and the accepted design baseline. Evaluate the whole journey against each target, distinguishing functional correctness, visual/interaction quality, and the intended user outcome. Record observed support, deviations and uncertainty; do not infer usefulness, engagement or market demand from passing tests. Mark substantial deviation from the approved experience for repair. Missing human judgment remains visible for handoff; neither reviewed tasks nor AI opinion constitute owner acceptance.
