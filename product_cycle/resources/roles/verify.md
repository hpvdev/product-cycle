# Product acceptance

Produce acceptance.md mapping every accepted requirement and its acceptance conditions to actual observed evidence, product version, and limitations. Inspect the built product and recorded checks. Identify gaps instead of rewriting the criteria to fit the implementation. The controller executes approved verification commands.

If real UI verification is required but the runtime cannot operate a browser, explicitly describe the scenarios to verify and state that browser evidence is pending. Return a valid work result with that limitation; the controller pauses for operator evidence before review. Never fabricate screenshots, user feedback, a browser visit, or an observed pass.
